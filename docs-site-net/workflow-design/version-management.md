# 流程版本管理

## 概述

AntFlowCore 提供完善的流程版本管理机制，支持流程模板的多版本共存、版本迁移和灰度发布。新版本发布后，已发起的流程继续按旧版本执行，新发起的流程使用新版本。

## 版本管理架构

```
┌─────────────────────────────────────────────────────────────┐
│                      流程版本管理                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  版本1 (已废弃)     版本2 (当前生效)     版本3 (草稿)        │
│  ┌──────────┐      ┌──────────┐      ┌──────────┐         │
│  │ 请假流程  │      │ 请假流程  │      │ 请假流程  │         │
│  │ v1       │      │ v2       │      │ v3       │         │
│  │ 已结束    │      │ 生效中    │      │ 编辑中    │         │
│  └──────────┘      └──────────┘      └──────────┘         │
│       │                 │                 │                 │
│       ▼                 ▼                 ▼                 │
│  在途流程继续      新流程使用         管理员核对              │
│  按v1执行          v2配置            后发布                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 版本状态

流程模板通过 `EffectiveStatus` 字段标识版本状态：

```csharp
// 源码位置: AntFlowCore.Base/entity/BpmnConf.cs
public int EffectiveStatus { get; set; }  // 生效状态 0=未生效，1=已生效
```

| 状态 | 值 | 说明 |
|------|---|------|
| 未生效 | 0 | 草稿状态，仅管理员可见，不可用于发起流程 |
| 已生效 | 1 | 正式发布状态，用户可发起流程 |

## 版本发布流程

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│  编辑流程    │ -> │  保存草稿    │ -> │  管理员核对  │ -> │  发布生效    │
│  Effective=0 │    │  Effective=0 │    │  Effective=0 │    │  Effective=1 │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                                                               │
                                                               ▼
                                                          ┌─────────────┐
                                                          │  旧版本自动  │
                                                          │  归档       │
                                                          └─────────────┘
```

## 版本生效接口

```http
GET /BpmnConf/effectiveBpmn/{id}
```

**源码实现**（`BpmnConfController.cs:164-168`）：

```csharp
/// <summary>
/// 生效一个流程模板,流程模板配置以后,默认是不生效的,要在页面上点击生效按钮方可生效
/// 为什么要这样设计?因为新设计的流程模板设计完之后管理员还要核对,看看是否要问题,
/// 如果设计完直接生效有错误就没法反悔了
/// </summary>
[HttpGet("effectiveBpmn/{id}")]
public Result<bool> EffectiveBpmn(int id)
{
    _bpmnConfService.EffectiveBpmnConf(id);
    return Result<bool>.Succ(true);
}
```

## 版本迁移

当流程模板升级时，AntFlowCore 支持将进行中的流程迁移到新版本：

```csharp
// 源码位置: AntFlowCore.Base/vo/BusinessDataVo.cs
/// <summary>
/// Whether this submit is a migration (dynamic condition re-evaluation) of a running
/// process. When true the original process number is reused and no new BpmBusinessProcess
/// is created; the existing one is updated with the new instance id.
/// </summary>
[JsonPropertyName("isMigration")]
public bool? IsMigration { get; set; }
```

### 迁移场景

1. **动态条件重评估**：流程运行中条件配置变更，需要重新评估流程路径
2. **流程模板升级**：将进行中的流程迁移到新版本模板
3. **节点插入/删除**：在运行中的流程中动态调整节点

### 迁移流程

```
┌─────────────────┐
│  流程正在运行    │
│  版本: v1       │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  管理员修改流程  │
│  保存为 v2      │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  触发迁移       │
│  isMigration=true│
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  在途流程继续    │
│  使用新配置      │
│  流程号不变      │
└─────────────────┘
```

## 版本兼容性

### 向前兼容

新版本发布后，已发起的流程不受影响，继续按原版本执行：

```
时间线:
──────────────────────────────────────────────────────────>

  t1: 发布v1        t2: 发布v2        t3: 发布v3
  │                 │                 │
  ▼                 ▼                 ▼
  ┌─────┐          ┌─────┐          ┌─────┐
  │ v1  │          │ v2  │          │ v3  │
  │生效  │          │生效  │          │生效  │
  └─────┘          └─────┘          └─────┘
       │                │                │
       ▼                ▼                ▼
  流程A(按v1)     流程B(按v2)      流程C(按v3)
  继续执行         新发起的流程      新发起的流程
```

### 版本回退

如需回退到旧版本，只需将旧版本重新生效：

```http
GET /BpmnConf/effectiveBpmn/{old_version_id}
```

## 灰度发布

AntFlowCore 支持灰度发布策略，通过 `BusinessPartyId` 和 `IsAll` 字段控制流程可见范围：

```csharp
// 源码位置: AntFlowCore.Base/entity/BpmnConf.cs
public int IsAll { get; set; }            // 是否全员可见 0=否，1=是
public long? BusinessPartyId { get; set; } // 业务方ID
```

### 灰度策略

| 策略 | IsAll | BusinessPartyId | 说明 |
|------|-------|-----------------|------|
| 全员发布 | 1 | null | 所有用户可见 |
| 指定业务方 | 0 | 指定ID | 仅特定业务方可见 |
| 指定人员 | - | - | 通过节点审批人规则控制 |

## 最佳实践

1. **版本命名**：使用有意义的版本号，如"v2.0-增加人事备案"
2. **版本说明**：每次版本变更记录变更原因和内容
3. **灰度发布**：重大变更先在小范围试用，确认无误后全员发布
4. **版本保留**：保留历史版本记录，便于追溯和回退
5. **迁移测试**：版本迁移前充分测试，确保在途流程不受影响
6. **生效前核对**：发布前使用预览功能验证流程正确性
