# 低代码 vs 自定义表单对比

## 概述

AntFlowCore 提供两种表单构建方式：**低代码表单（Low Code Form）** 和 **DIY 自定义表单**。两种方式各有适用场景，开发者可根据业务需求灵活选择。

## 架构对比

### 低代码表单架构

```
┌─────────────────────────────────────────────────┐
│              前端 vform 设计器                    │
│         拖拽控件 → 生成 JSON Schema              │
└─────────────────────┬───────────────────────────┘
                      │ JSON
                      ▼
┌─────────────────────────────────────────────────┐
│           LowCodeFlowController                  │
│  createLowCodeFormCode / getformDataByFormCode   │
└─────────────────────┬───────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────┐
│         BpmnConfLfFormdata 表                    │
│         存储完整 JSON 表单定义                    │
└─────────────────────────────────────────────────┘
```

### DIY 自定义表单架构

```
┌─────────────────────────────────────────────────┐
│              前端自由开发                          │
│     Vue/React 任意组件 → 自定义表单页面            │
└─────────────────────┬───────────────────────────┘
                      │ 业务数据
                      ▼
┌─────────────────────────────────────────────────┐
│        IFormOperationAdaptor 接口                │
│   开发者实现 GetFormContent / SaveFormData       │
└─────────────────────┬───────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────┐
│           自定义业务表存储                         │
│        开发者自行设计表结构                        │
└─────────────────────────────────────────────────┘
```

## 详细对比

### 开发模式

| 维度 | 低代码表单 | DIY 自定义表单 |
|------|-----------|---------------|
| **表单创建** | 拖拽设计器，零代码 | 前端硬编码或模板生成 |
| **数据存储** | JSON 统一存储 | 关系型表结构 |
| **字段管理** | 设计器配置 | 数据库建表 + 前端绑定 |
| **流程关联** | formCode 字典关联 | 实现适配器接口关联 |
| **条件引用** | 自动解析 JSON 字段 | 实现条件变量提供方法 |

### 技术实现

#### 低代码表单核心代码

```csharp
// 低代码表单 - 通过 formCode 获取表单定义
[HttpGet("getformDataByFormCode")]
public Result<string> GetLFFormDataByFormCode(string formCode)
{
    if (string.IsNullOrEmpty(formCode))
    {
        throw new AFBizException("请传入formcode"); 
    }
    BpmnConfLfFormdata lfFormDataByFormCode = 
        _lfformDataBizService.GetLFFormDataByFormCode(formCode);
    return ResultHelper.Success(lfFormDataByFormCode.Formdata);
}
```

#### DIY 自定义表单核心接口

```csharp
// DIY 表单 - 开发者需要实现的适配器接口
public interface IFormOperationAdaptor
{
    // 获取表单内容（返回HTML或JSON）
    string GetFormContent(string formCode);
    
    // 保存表单数据
    void SaveFormData(string formCode, string formData);
    
    // 获取表单字段值（用于条件判断）
    object GetFieldValue(string formCode, string fieldKey);
}
```

### 性能对比

| 指标 | 低代码 | DIY |
|------|--------|-----|
| 首次加载 | 需要加载 JSON 定义 | 直接渲染 |

## 选择建议

### 选择低代码表单的场景

1. **标准审批流程**：请假、报销、出差、采购等通用审批
2. **快速上线需求**：需要在数小时或数天内完成部署
3. **无专职前端**：团队缺乏前端开发人员
4. **表单变更频繁**：业务规则经常调整，需要快速响应
5. **内部管理系统**：OA、CRM、HR 等内部管理工具

### 选择 DIY 自定义表单的场景

1. **复杂业务逻辑**：表单字段之间有复杂的联动和计算规则
2. **深度系统集成**：需要与 ERP、SAP 等外部系统实时交互
3. **特殊 UI 需求**：需要图表、地图、富文本编辑器等特殊组件
4. **高性能要求**：大数据量展示、高并发提交
5. **移动端优先**：需要针对移动端做深度优化

## 混合使用策略

在实际项目中，两种模式可以共存：

```
┌─────────────────────────────────────────────────┐
│              流程模板配置                         │
│                                                  │
│  节点A（发起） ─── 低代码表单（标准字段收集）      │
│       │                                          │
│  节点B（审批） ─── DIY 表单（需要集成ERP查询）     │
│       │                                          │
│  节点C（备案） ─── 低代码表单（标准信息登记）      │
└─────────────────────────────────────────────────┘
```

### 实现方式

在流程模板中，不同节点可以配置不同类型的表单：

```json
{
  "nodes": [
    {
      "nodeId": "start",
      "formCode": "standard_leave_form",
      "formType": "lowcode"
    },
    {
      "nodeId": "manager_approval",
      "formCode": "diy_manager_form",
      "formType": "diy"
    }
  ]
}
```

## 迁移指南

### 从低代码迁移到 DIY

当低代码表单无法满足需求时，可以平滑迁移：

1. 实现 `IFormOperationAdaptor` 接口
2. 在自定义表单中实现原有低代码表单的功能
3. 修改流程模板中的 formCode 指向新的 DIY 表单
4. 历史数据保持兼容（低代码 JSON 数据仍保留）

### 从 DIY 迁移到低代码

当业务稳定后，可考虑迁移到低代码以降低维护成本：

1. 在 vform 设计器中重建表单布局
2. 配置相同的字段类型和校验规则
3. 更新流程模板中的 formCode
4. 保留 DIY 表单代码作为备份

## 总结

低代码表单和 DIY 自定义表单在 AntFlowCore 中并非互斥关系，而是互补的两种能力。低代码解决"快"和"简"的问题，DIY解决"深"和"广"的问题。合理选择或组合使用两种方式，才能最大化发挥 AntFlowCore 的价值。
